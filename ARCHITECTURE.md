# 🏗️ Tamweel AI — Complete System Architecture

This document provides a comprehensive map of the Tamweel AI platform's directory structure, module responsibilities, and systemic interactions.

---

## 1. Top-Level Directory Structure

The repository follows a clean, decoupled monorepo structure. Each component is strictly separated by its architectural domain.

```text
Tamweel_test/
├── .github/              # CI/CD pipelines
├── backend/              # FastAPI Application (API & Orchestration)
├── frontend/             # React SPA (User & Sponsor Interfaces)
├── ml_pipeline/          # ML Training & RAG Prototyping Pipeline
├── database/             # PostgreSQL Schema & Migrations
├── tests/                # Automated CI/CD Pytest Suite
├── scripts/              # Developer scripts & manual test fallbacks
├── docs/                 # Archived logs & old diagnostics
├── .env.example          # Safe environment variables template
├── .gitignore            # Git exclusion rules
├── docker-compose.yml    # Multi-container orchestration (Backend + Frontend + Redis)
├── launch_tamweel.py     # Local developer quick-start script
├── README.md             # Primary project documentation
└── SECURITY.md           # FinTech ethical AI & security specs
```

## 2. Detailed Folder Breakdown

### `backend/`
The core API server built on FastAPI. It acts as the orchestrator connecting the React frontend to the Supabase database and the ML inference engine.
- **`Dockerfile`**: Multi-stage Docker configuration for production deployment.
- **`requirements.txt`**: Python dependencies.
- **`app/`**: The main application code.
  - **`main.py`**: The FastAPI application entry point. Wires up routers, CORS, and startup events.
  - **`schemas.py`**: Pydantic models enforcing strict input/output validation.
  - **`utils.py`**: Centralized helper functions (e.g., timezone-aware ISO date parsing, stopword lists).
  - **`routes/`**: Modular API endpoints.
    - `auth.py`: JWT generation, login, and registration.
    - `chat.py`: LLM Assistant interactions.
    - `score.py`: Credit score submission and generation.
    - `users.py`: Financial intelligence, transaction history, and portfolio fetching.
    - `admin.py`: PDF policy ingestion routes.
  - **`ml/`**: Machine Learning inference layer.
    - `hybrid_engine.py`: Loads the serialized XGBoost models, validates features, computes the base risk, enforces deterministic business rules, and outputs the final credit decision.
    - `models/`: Symlink directory to the serialized `.pkl` files generated by the MVP pipeline.
  - **`services/`**: Business logic and data retrieval.
    - `financial_intelligence.py`: Computes 6-month transaction volatility and savings rates.
    - `redis_cache.py`: Interacts with Redis to cache identical LLM generic queries (24h TTL).
    - `intent_classifier.py`: Routes user questions to either specific DB queries or the generic RAG pipeline.
    - `context_assembler.py`: Combines retrieved policy chunks and user financial data into the final LLM prompt.
  - **`pipeline/`**: The RAG (Retrieval-Augmented Generation) infrastructure.
    - `embed.py`: Calls OpenAI to generate 768d embeddings.
    - `query_rewriter.py`: Uses DeepSeek to expand ambiguous user follow-up questions.
    - `extract.py`: Parses PDFs via PyMuPDF.

### `frontend/`
The user interface, built with React 19, Vite, and Tailwind CSS v4.
- **`Dockerfile`**: Multi-stage build deploying the built assets to an Nginx server.
- **`package.json`**: Node.js dependencies.
- **`src/`**: React source code.
  - **`features/`**: Domain-driven component design.
    - `dashboard/`: Contains `UserDashboard.jsx` (applicant view), `SponsorDashboard.jsx` (admin view), `CreditScoreGauge.jsx` (animated UI), and `SpendingAnalytics.jsx`.
    - `auth/`: Login and registration forms.
    - `admin/`: Knowledge base upload interfaces (`AdminKnowledgeUpload.jsx`).
  - **`contexts/`**: React Context API for global state management.
  - **`hooks/`**: Custom reusable React hooks.
  - **`services/`**: API wrapper functions standardizing HTTP calls to the backend.
  - **`store/`**: Zustand global state stores.
  - **`routes/`**: Protected route logic preventing unauthorized dashboard access.

### `ml_pipeline/`
The standalone Machine Learning research and training pipeline. It operates independently from the backend to ensure training dependencies do not bloat the API server.
- **`generate_data.py`**: Synthesizes 5,000+ records of structurally realistic financial data based on latent probability functions.
- **`train_model.py`**: The core ML pipeline. Cleans data, trains the XGBoost model, applies `CalibratedClassifierCV` for accurate probability mapping, and exports artifacts.
- **`rag_engine.py`**: Prototype script utilized to test LLM prompts before migrating them to `backend/app/pipeline/`.
- **`models/`**: Stores the output artifacts (`.pkl` and `.json`) used by the backend inference engine.
- **`data/`**: Stores the output CSVs generated by `generate_data.py`.

### `database/`
All PostgreSQL schemas, tables, and Remote Procedure Calls (RPCs) utilized in Supabase.
- **`credit_decision_audit_log.sql`**: Immutable ledger schema tracking every ML score and variable.
- **`hybrid_search_schema.sql`**: `pgvector` implementation for reciprocal rank fusion (RRF) search across policy documents.
- **`transaction_module.sql`**: Tables for tracking user income and expenses.
- **`add_role_column.sql`**: Role-Based Access Control (RBAC) migration script.
- *(Other seed and connection schemas).*

### `tests/`
The automated CI/CD test suite run by GitHub Actions.
- **`test_ml.py`**: Asserts the XGBoost models load and predict correctly without backend interference.
- **`test_api.py`**: Utilizes `fastapi.testclient` to ensure endpoints return proper HTTP status codes.
- **`test_hybrid_engine.py`**: Ensures the business rule firewall overrides ML scores deterministically.
- **`test_rag.py`**: Verifies retrieval pipelines enforce citation formats.
- **`test_security.py`**: Validates JWT authentication blocks.

### `.github/`
- **`workflows/ci.yml`**: GitHub Actions definition. Runs Python `flake8` linting, the `pytest` suite, and a Node.js frontend build on every push to `main` or `develop`.

## 3. Data Flow Architecture

1. **User Interaction**: User interacts with React Frontend (`frontend/src/features/dashboard/UserDashboard.jsx`).
2. **API Request**: Request hits the FastAPI Router (`backend/app/routes/score.py`), which validates the JWT via `auth.py`.
3. **ML Inference**: `hybrid_engine.py` loads user data, passes it through `scaler.pkl`, and requests a probability score from `tamweel_xgboost_classifier.pkl`.
4. **Business Firewall**: The probability score is subjected to hardcoded business rules (e.g., if income < 50 JOD, auto-reject regardless of ML score).
5. **Database Audit**: The exact input vectors, ML output, and final decision are permanently logged to the `credit_decision_audit_log` table in Supabase.
6. **LLM Explanation**: The numeric decision is passed as a *read-only* variable to the `context_assembler.py`. DeepSeek/Claude generates an Arabic explanation strictly citing why the user received that specific score.
7. **Response**: The explanation and score are returned to the frontend and rendered in the animated `CreditScoreGauge.jsx`.
